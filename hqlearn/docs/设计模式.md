## 定义
设计模式是软件开发中针对常见问题的可服用解决方案。提供了标准化的设计思路，帮助开发者编写更易维护、扩展、可读性更强的代码。
## 核心价值
-   复用性
-   可维护性
-   可扩展性
-   沟通效率
## 分类
《设计模式：可复用面向对象软件基础》提出23种模式，分为三大类

### 创建型模式
关注对象创建过程的优化，隐藏创建细节，降低代码耦合。
#### 单例模式
确保类只有**唯一实例**，并提供全局访问点
##### 饿汉式
程序启动时就创建实例，线程安全，但是可能提前占用资源
```
class Singleton{
private:
    //私有构造函数
    Singleton() = default;
    //禁止拷贝和赋值
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
    //静态成员变量
    static Singleton instance;
public:
    //全局访问点
    static Singleton& GetInstance(){
        return instance;
    }
}
```
使用场景：单例对象体积小、初始化快，且肯定会被使用
##### 懒汉式
只有第一次使用时才创建，但是多线程环境可能创建多个实例
```
class Singleton{
private:
    //私有构造函数
    Singleton() = default;
    //禁止拷贝和赋值
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
    //静态指针（延迟初始化）
    static Singleton* instance;
public:
    static Singleton& GetInstance(){
        if(instance == nullptr){
            instance = new Singleton(); //多线程可能同时进入此处
        }
        return *instance;
    }
}
```
多线程并发调用 GetInstance() 时，可能同时通过 if (instance == nullptr) 判断，导致创建多个实例。
##### 懒汉式（线程安全版，C++11前）
```
#include <mutex>

class Singleton {
private:
    Singleton() = default;
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
    
    static Singleton* instance;
    static std::mutex mtx; // 互斥锁

public:
    static Singleton& GetInstance() {
        std::lock_guard<std::mutex> lock(mtx); // 加锁（自动释放）
        if (instance == nullptr) {
            instance = new Singleton();
        }
        return *instance;
    }
};

Singleton* Singleton::instance = nullptr;
std::mutex Singleton::mtx;
```
##### 局部静态变量式（C++11 及以上，推荐）
```
class Singleton {
private:
    Singleton() = default;
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

public:
    // 局部静态变量：第一次调用时初始化，且仅一次
    static Singleton& GetInstance() {
        static Singleton instance; 
        return instance;
    }
};
```

#### 外观模式（Facade）
为复杂系统提供简化接口，隐藏内部复杂性。
#### 组合模式（Composite）
统一处理 "单个对象" 和 "对象集合"，形成树形结构。

### 行为型模式（Behavioral Patterns）
关注对象间的交互与职责分配，优化通信逻辑。

#### 观察者模式（Observer）
定义 "一对多" 依赖关系，当一个对象变化时，自动通知所有依赖者。
例：GUI 事件监听（按钮点击通知多个响应函数）
#### 策略模式（Strategy）
定义算法家族，封装不同实现，允许动态切换。
#### 模板方法模式（Template Method）
父类定义算法骨架，子类实现具体步骤（固定流程，灵活细节）。
例：做菜模板（固定 "备料→烹饪→装盘"，子类实现具体菜品）
 ####迭代器模式（Iterator）
提供统一接口遍历集合，隐藏集合内部结构。
例：Java 的 Iterator、Python 的 for 循环
#### 责任链模式（Chain of Responsibility）
将请求传递给多个处理者，直到被处理（解耦请求与处理）。
例：请假审批流程（组长→经理→总监）
